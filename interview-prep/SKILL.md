# 面试前准备策略生成

基于岗位 JD，结合候选人实习经历和历史复盘经验，生成一份可直接用于面试前复习的完整策略文档。

## 适用范围

**适合**：以**简历深挖、案例题、行为题**为主的面试，常见于职能类 / 业务类岗位。

## 用户信息

在工作流程开始前，需通过步骤零建立候选人完整档案。档案直接用于生成自我介绍、经历对应表和项目深挖策略，是本 skill 最核心的输入之一。

- 用户身份：候选人（学历背景、实习经历、项目数据口径、求职方向均由步骤零收集）

---

## 工作流程

### 步骤零：建立候选人完整档案

在生成面试准备策略之前，需要建立候选人的完整档案。

**如果用户已在本次对话中提供过完整个人信息，直接使用，跳过此步骤。**

---

**方式一：读取简历（强烈推荐）**

如果用户提供简历文件路径（PDF、Word、Markdown 均可），用 Read 工具读取，提取以下信息：

- **学历背景**：学校名称、专业、学历层次、毕业年份
- **求职方向**：目标岗位类型
- **实习经历清单**：每段实习的公司名称、岗位名称、时间段、主要项目和职责
- **项目关键数字**：样本量、指标数量、准确率、覆盖规模等可用于佐证的数据

读取后，整理为如下格式并向用户确认：

```
我从你的简历中整理了以下信息，请确认是否准确，有遗漏或错误请直接告诉我：

学历：[学校] [专业] [学历]，预计 [年份] 年毕业

实习经历：
- [公司A] | [岗位] | [时间]：[核心工作一句话]
- [公司B] | [岗位] | [时间]：[核心工作一句话]

项目关键数据：
- [项目A]：[数字1]、[数字2]
- [项目B]：[数字1]
```

**方式二：引导提问**

如果没有简历可提供，依次提问（每次只问一个，等用户回复后再问下一个）：

1. "你的学历背景是什么？（学校 + 专业 + 学历层次，如：XX 大学 XX 专业硕士）"
2. "你有哪些主要的实习或项目经历？请列出公司名、岗位名，以及主要做了什么。"
3. "这些项目中有没有可以引用的关键数字？（如样本量多少人、分析了多少条数据、达到了什么准确率或指标提升）"
4. "你主要在求职什么方向的岗位？"

**方式三：用户直接提供**

用户可以一次性粘贴个人信息，例如："我是 XX 大学 XX 专业应届硕士，主要实习是 XX 公司 XX 岗位（做了 XX 项目，样本量 XX，关键指标 XX），以及 XX 公司 XX 岗位（做了 XX 项目）。现在求职 XX 类岗位。"

档案确认完成后，继续步骤一。

### 步骤一：确认输入与输出路径

用户会提供以下信息：

- **JD**（必须）：文件路径或直接粘贴文本
- **公司名称、岗位名称、面试轮次**（必须，如未提供则从 JD 中识别）
- **历史复盘文件路径**（可选）：上一场或多场同岗位复盘文件，用于提取历史教训
- **行业背景材料**（可选）：如已有行业调研文件，一并读取
- **面经信息**（可选）：见下方说明

用 Read 工具读取所有输入文件。

**面经信息的获取方式**

面经信息用于了解该公司/岗位的真实面试风格——面试官通常问什么类型的问题、是否有固定套路、有哪些高频考察点。

- **方式一：用户提供本地文件**：如果用户已保存过面经文档，提供文件路径，用 Read 工具读取。
- **方式二：在线搜索**：如果用户没有本地面经，且公司名称和岗位已确认，可以主动询问一次："需要我在网上搜索一下 [公司]-[岗位] 的面经吗？（会使用网络搜索）" 用户确认后，使用 WebSearch 工具搜索，关键词格式参考：`[公司] [岗位] 面经 2025` 或 `[公司] [岗位] 面试 题目`。提取其中的高频问题和面试风格描述，用于步骤二的"岗位特殊性判断"和第五节"高频题预测"。
- 如果用户明确不需要，跳过此项，不再询问。

**确定输出路径规则**：
- 检查 `面试复盘管理/` 目录下是否已有 `[公司]-[岗位]/` 文件夹
  - 如有：直接在该目录下创建准备文件
  - 如无：在 `面试复盘管理/[公司]-[岗位]/` 下创建（目录不存在时自动创建）
- 文件名：`[公司简称]-[岗位简称]-[轮次]准备.md`
- 示例：`[公司A]-[岗位]-一面准备.md`、`[公司B]-[岗位]-二面准备.md`

### 步骤二：分析 JD，识别岗位特殊性

从 JD 中提取以下信息：

1. **公司/业务背景**：这家公司核心做什么，目标岗位在其中的位置是什么
2. **岗位核心考察点**：这份 JD 最看重的 4-5 件事（不是把 JD 翻译一遍，而是判断真实考察重点）
3. **岗位特殊性判断**：
   - 和同类岗位相比，这个岗位的特别之处是什么
   - 它在考察什么是"同类岗位通常不考的"
   - 面试官最可能在哪个方向深挖（方法、业务理解、落地能力、工具能力、行业背景等）

### 步骤三：生成完整策略文档

## 注意事项

**内容生成原则**

- JD 拆解要有判断，不能只是把 JD 翻译一遍——要说清楚"面试官真正在看什么"
- 经历对应表要给出**面试里的具体表述方式**，不只是说"用这段经历"
- 自我介绍必须口语化，不要书面语，每一层设计意图都要说明
- 高频题答法要给出**可直接复述的答案**，不只是答题框架
- 项目深挖策略的"推荐答法"必须模拟真实面试语气，开头先给结论，再展开证据
- 历史教训防范清单要具体：写"遇到___时做___"，不要写"注意答题结构"
- 反问备选要和这家公司/这个岗位有实质联系，不要通用问题

**结构取舍原则**

- 如果提供了历史复盘，第八节（历史教训）要基于复盘中识别出的真实问题，而不是凭空猜测
- 如果岗位和以往岗位差异较大（如跨行业、跨岗位类型），第零节（背景认知）要写得更充分
- 如果面试是二面及以上，要在策略里专门说明二面和一面侧重的不同（一面通常问执行，二面通常问判断力/领导力/战略理解）
- 项目深挖策略的数量根据 JD 侧重点决定：如果 JD 强调某个项目类型，则对该类型项目的深挖篇幅相应加大

**风格原则**

- 参考答法的语气：自然口语，有结构但不机械，开头先给结论
- 临场提醒的语气：简短、直接，像贴在桌上的便利贴
- 历史教训的语气：具体、可执行，不是泛泛的"注意某某方面"
- 数字不漂移：文档中所有数字使用统一的固定说法，和候选人实际情况吻合
