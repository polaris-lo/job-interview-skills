# 面试录音文本整理

将苹果语音备忘录等工具产出的原始转文字文本（无标点结构、无说话人、无时间戳）整理为结构化访谈记录，并写入文件。

## 用户信息

在工作流程开始前，需通过步骤零确认候选人基础信息，用于准确识别说话人和理解面试专业术语。

- 用户身份：候选人（学历、专业、求职方向由步骤零收集）
- 说话人 1（面试官）：提问方，通常问题较短，使用"你/您"
- 说话人 2（候选人）：回答方，回答内容较长，有大量"就是""然后""呃"等口头语

## 工作流程

### 步骤零：确认候选人基础信息

在整理转文字之前，确认候选人的基本背景，以便准确识别说话人、理解专业术语。

**如果用户已在本次对话中介绍过自己，直接使用已知信息，跳过此步骤。**

通过以下任一方式获取：

- **用户直接说明**：如"我是 XX 大学 XX 专业硕士，应聘 XX 岗位"
- **读取简历**：如果用户提供了简历文件路径，用 Read 工具读取，提取学历背景和求职方向
- **引导提问**（如以上都没有）：只问一个问题——"请简单介绍一下你的背景：你是哪个专业的，在应聘什么方向的岗位？"

获取信息后，继续步骤一。

### 步骤一：确认输入文件路径

用户会提供原始录音转文字文件的路径，或者直接粘贴文本内容。

如果用户提供了文件路径（如 `面试复盘管理/某公司-某岗位/面试录音原文.md`），先用 Read 工具读取该文件。

**确定输出路径规则**：
- 输出文件保存在与原文件**同一目录**下
- 文件名：`[原文件名去掉"原文"或"录音"字样]-精校版.md`
- 示例：`面试录音原文.md` → `面试录音精校版.md`
- 如果文件名不含"原文"/"录音"，则直接加后缀：`XXX-精校版.md`

### 步骤二：通读原文，识别说话人

通过以下特征区分两类说话人：

**面试官的语言特征**
- 提出问题或引导性表述（"能不能说说…""那你觉得…""我想问一下…"）
- 句子相对简短，不超过 2-3 句话
- 使用"你/您"称呼候选人
- 对候选人的回答进行追问（"嗯，那…""好，那如果…"）
- 介绍公司/岗位信息（通常在面试后期）
- 说"好的""嗯，了解"等简短回应后接下一个问题
- 面试开头的寒暄、自我介绍（"我是本次的面试官…"）
- 面试结尾的收尾语（"今天先到这里…"）

**候选人的语言特征**
- 回答篇幅明显更长
- 以"我"为主语叙述过去经历
- 大量出现"就是""然后""呃""对"等填充词
- 描述具体项目背景、过程、结论
- 有时以"好，嗯，尊敬的面试官…"开头（自我介绍段）
- 在面试后期会反问面试官（"我想问一下…""我有一个问题…"）

**特殊情况处理**
- 如果某段无法确定说话人，根据上下文判断，倾向于把短促回应归为面试官、长篇叙述归为候选人
- 候选人有时会模拟面试官的问题再回答——这仍然属于候选人发言，不要切分为面试官
- 如果录音只保留了候选人声音（面试官问题缺失），在文本中标注 `[面试官提问，未录入]`，并根据候选人的回答倒推推断问题

### 步骤三：切分说话人轮次

按照对话轮次切分，每个说话人轮次之间空一行。同一说话人连续发言时，如果话题延续可以合并为同一轮次。

格式：
```
**面试官**：[内容]

**候选人**：[内容]
```

### 步骤四：段内分段排版

对候选人的长篇回答进行段内细分，遵循以下排版规则：

- 每换一个语义层次或话题，另起一段
- 如果候选人使用"首先…其次…第三…""一是…二是…"等结构，全部改为 bullet points 分点列举
- 去除多余填充词（"就是""然后""呃"可适当精简，但保留整体语气，不要改变措辞或意思）
- 不要改变任何实质内容或数字

面试官的简短发言通常不需要再分段。

### 步骤五：组装文档内容

完整文档结构：

```markdown
## 面试摘要

**公司 / 岗位**：[从文本中识别，如无法确认则留空]
**面试轮次**：[一面 / 二面 / HR面 / 未知]
**面试时长**：[如可识别则填写]
**日期**：[如可识别则填写]

### 主要提问主线

1. [问题1简述]
2. [问题2简述]
（按面试中出现的顺序列出所有主要问题）

### 候选人表现亮点

- [根据回答内容归纳，1-3 条]

### 值得关注的薄弱点

- [根据回答内容归纳，1-3 条]

---

[完整对话正文，按面试官/候选人轮次排版]
```

### 步骤六：写入文件

使用 Write 工具将完整文档内容写入步骤一确定的输出路径。

写入完成后，在对话框中只输出一行确认信息：

```
已保存：[输出文件的完整路径]
```

不要在对话框里输出文档内容本身。

## 注意事项

- 保留候选人回答的原始措辞和数据，不要"改善"内容
- 精简填充词时以自然为准，不要把整段话都改得太书面
- 如果原文出现明显的语音识别错误（如同音字错误、语义不通），可在 `[括号内]` 标注修正，但不要静默替换
- 摘要中的"薄弱点"要客观，基于文本事实，不要随意评价候选人
