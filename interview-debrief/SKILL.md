# 面试复盘文档生成

基于面试录音文字记录（可以是已经过 interview-transcript 整理的精校版，也可以是原始转文字），生成结构化复盘文档并写入文件。

## 适用范围

**适合**：以**简历深挖、案例题、行为题**为主的面试，常见于职能类 / 业务类岗位。

## 用户信息

在工作流程开始前，需通过步骤零确认候选人档案。档案用于评估回答质量、判断岗位匹配度、生成针对性的改进建议。

- 用户身份：候选人（学历、专业、主要经历、求职方向由步骤零收集）
- 面试场景：企业面试，岗位方向由步骤零确认
- 复盘目的：识别回答中的不足，提炼改进点，为下一场面试准备更好的参考答案

## 工作流程

### 步骤零：确认候选人档案

在开始复盘之前，了解候选人的背景信息，以便准确评估回答质量和岗位匹配度。

**如果用户已在本次对话中提供过个人信息，直接使用，跳过此步骤。**

通过以下任一方式收集候选人档案：

**方式一：读取简历（推荐）**

如果用户提供简历文件路径，用 Read 工具读取，提取：
- 学历背景（学校、专业、学历层次）
- 求职方向
- 主要实习/项目经历（公司、岗位、核心工作内容一句话）

读取后向用户确认："我从简历中了解到你的背景是 [提炼内容]，接下来按此进行复盘。如有出入请纠正。"

**方式二：引导提问**

依次提问（每次只问一个，等用户回复后再问下一个）：

1. "你的学历和专业背景是什么？"
2. "你在求职哪类岗位方向？（如：产品、运营、数据分析、设计等）"
3. "你最主要的实习经历是什么？（公司 + 岗位 + 核心项目，一两句话即可）"

**方式三：用户直接提供**

用户可以直接粘贴基础信息，例如："我是 XX 大学 XX 专业应届硕士，做过 XX 公司 XX 岗位的实习，现在求职 XX 类岗位。"

收集完成后，继续步骤一。

### 步骤一：确认输入与输出路径

用户会提供以下任意一种输入：
- 精校版文字记录文件路径（interview-transcript 的输出，推荐）
- 原始录音转文字文件路径
- 直接粘贴文本

用 Read 工具读取文件。如果用户同时提供了 JD 文件，也一并读取。

如果用户没有提供 JD，询问一次："有没有这个岗位的 JD？提供的话评估匹配度会更准确。"（只问一次，不强求）

**确定输出路径规则**：
- 输出文件保存在与输入文件**同一目录**下
- 文件名：`[公司简称]-[岗位简称]-[轮次]复盘.md`
- 从文本内容中识别公司名、岗位名、轮次
- 示例：`[公司A]-[岗位简称]-一面复盘.md`、`[公司B]-[岗位简称]-二面复盘.md`
- 如果无法识别，使用 `面试复盘-[日期].md`

### 步骤二：提取岗位基本信息

从文本中识别：
- 公司名称
- 岗位名称
- 面试轮次（一面/二面/HR面）
- 面试时间（如可识别）
- 面试状态（等待结果 / 通过 / 未通过 / 未知，默认填"等待结果"）

### 步骤三：还原问题列表

逐一识别面试官提出的所有问题。每个问题对应候选人的一段完整回答。

还原规则：
- 如果面试官发言可识别，直接引用或改写为标准问句
- 如果录音只录到候选人（面试官声音缺失），根据候选人的回答倒推推断问题，并标注 `（根据回答推断）`
- 追问算独立问题

同时记录可观察到的面试官跟进行为，用于步骤四的评估校准：
- 面试官在此题之后有无追问
- 面试官有无主动挑战或反驳
- 面试官是否直接进入下一题（无任何跟进）
- 面试官对某题连续追问几次

这些行为本身是评估信号：连续追问 = 考察点被激活或发现答案有缺口；无任何追问 = 答案已满足或面试官投入度不高（需结合全场判断）；主动挑战 = 真实考察该题，回答质量影响权重更大。

### 步骤四：逐题生成评估

对每个问题，生成以下结构：

```markdown
### Q[编号]：[问题标题]

**我的回答要点**

- [提炼的要点1]
- [提炼的要点2]
（按候选人实际说的内容提炼，不添加、不美化）

**面试官反应**

[描述面试官在此题之后的行为：无追问直接进入下一题 / 追问了X次 / 主动挑战或反驳 / 追问后转移话题]
（这是评估校准的重要输入，影响该题评分的权重解读）

**评估**

| 维度 | 评分 | 备注 |
| ---- | ---- | ---- |
| [维度1] | ⭐⭐⭐ | [具体说明] |
| [维度2] | ⭐⭐ | [具体说明] |

**可改进**

1. [具体改进点，说明问题在哪里、怎么改]
2. [具体改进点]

**更优答法**

- [从表达结构、业务视角、方法逻辑或洞察深度出发，说明如果重新回答，这题怎么答会更好]
- [尽量给出可直接复述的说法，而不是只有抽象建议]
- [如适用，可拆成“先讲什么、再讲什么、最后怎么收”]

**参考答案**（可选，如有明确改进空间则提供）

> [更好的表达方式或结构框架]
```

其中，`**更优答法**` 为**每一道题的必选项**，不可省略。即使该题整体回答较好，也必须补充“如果想答得更出色，可以怎么组织表达、怎么更有业务感、怎么更有结构”。

**评估维度选择原则**

根据题目类型选择 3-5 个最相关的维度：

| 题目类型 | 常用评估维度 |
| -------- | ------------ |
| 自我介绍 | 逻辑结构、与JD匹配度、表达流畅度、亮点突出度 |
| 行为题（项目经历） | STAR结构、技术/方法深度、与岗位迁移价值、表达流畅度 |
| 情境题（如果遇到X你会怎么做） | 思维框架、实操可行性、结构化程度 |
| 数据分析题 | 方法匹配度、思路清晰度、数字/工具的具体性 |
| 职业规划 | 与岗位方向一致性、成长路径合理性、表达真诚度 |

**评分标准**

- ⭐⭐⭐⭐⭐：非常出色，无明显问题
- ⭐⭐⭐⭐：良好，有小改进空间
- ⭐⭐⭐：中等，有明确改进点
- ⭐⭐：偏弱，需要重点改进
- ⭐：明显缺失或失误

### 步骤五：生成整体复盘总结

```markdown
---

## 二、整体复盘

### 面试官信号解读

**提问行为信号**：回顾全场，哪些题目面试官有追问 / 挑战 / 无反应，对照回答质量做出解读。
例如：某题被连续追问两次 = 面试官认为答案不充分，该题权重高于看起来；某题无任何追问 = 答案已满足或面试官投入度不高。

**反问环节信号**：候选人向面试官提问岗位工作内容时，评估面试官的回答质量。

| 候选人提问 | 面试官回答详细程度 | 评估 |
| ---------- | ------------------ | ---- |
| [候选人问题1] | 高/中/低——[说明回答是否超出JD、是否提及具体现状或挑战] | 偏好/中性/偏弱 |
| [候选人问题2] | … | … |

**评估标准**：
- 高（好信号）：面试官主动介绍当前团队实际情况、在做什么项目、遇到什么挑战，像在"卖"这个岗位
- 中（中性）：回答有内容但基本停留在 JD 层面，没有超出书面信息
- 低（弱信号）：回答一两句话即结束，或答案非常笼统，没有任何具体信息

---

### 本场表现总结

| 方面 | 评价 |
| ---- | ---- |
| 内容准备度 | [评价] |
| 表达与流畅度 | [评价] |
| 与岗位的匹配呈现 | [评价] |
| 临场应变 | [评价] |

### 本场最需改进的 3 件事

1. [最重要的改进点]
2. [第二重要]
3. [第三重要]

### 下场面试准备建议

- [针对此次薄弱点的具体准备建议]
```

### 步骤六：组装完整文档

```markdown
# [公司名称] [招募批次/年份]｜[岗位名称] [轮次]复盘

**面试时间**：[时间]
**形式**：[面试形式]
**状态**：等待结果

---

## 一、问题还原与回答评估

[逐题内容]

---

## 二、整体复盘

[总结内容]
```

### 步骤七：写入文件

使用 Write 工具将完整文档写入步骤一确定的输出路径。

写入完成后，在对话框中只输出一行确认信息：

```
已保存：[输出文件的完整路径]
```

不要在对话框里输出文档内容本身。

## 注意事项

- 回答要点只提炼实际说的内容，不要帮候选人美化或补充没说的东西
- 评估要客观，有理有据，不要空洞表扬或过度批评
- "可改进"要具体：指出问题所在，给出可操作的改法
- `更优答法` 必须是每题固定步骤，不可遗漏；重点是告诉用户“这题下次怎么答会更强”，尽量落到结构提示、表达顺序和可直接复述的话术层面
- 参考答案不是强制项，只在真的有更好的表达时提供；不要用过于完美的模板答案覆盖候选人的真实风格
- 如果某个问题候选人回答得很好，评估如实说好，不要为了显得有价值而硬挑毛病
- 即使某题评分较高，也仍然要给出“更优答法”，说明怎样从 4 星答到更出色，而不是只给低分题改进建议
- 排版遵循用户偏好：语义分段，多分段，论点用 bullet points 分行列举
